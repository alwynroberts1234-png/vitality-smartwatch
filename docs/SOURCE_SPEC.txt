15. Display buffering

A full 466×466 RGB565 frame is approximately:

466 × 466 × 2

≈ 434 KB

The nRF52840 only has:

256 KB RAM

so never allocate a full framebuffer.

Use LVGL partial buffers.

For example:

#define DISPLAY_WIDTH 466
#define DISPLAY_BUFFER_LINES 40

static lv_color_t buf1[
    DISPLAY_WIDTH *
    DISPLAY_BUFFER_LINES
];

static lv_color_t buf2[
    DISPLAY_WIDTH *
    DISPLAY_BUFFER_LINES
];

Memory:

466 × 40 × 2
≈ 37 KB

Two buffers
≈ 74 KB

Much more practical.

Architecture rules:

1. Drivers must not call UI code.
2. UI must not directly access hardware drivers.
3. Sensor data flows through sensor_manager.
4. Application communication uses an event bus.
5. Large UI assets live in external QSPI.
6. LVGL loads assets through a Q: filesystem.
7. Use partial LVGL display buffers.
8. Use Zephyr power management.
9. All hardware drivers must support suspend/resume.
10. Use MCUboot for firmware updates.
11. Keep modules unit-testable.
12. Do not implement fake glucose measurements.
13. Reserve an interface for a future validated CGM/biosensor.

- public headers
- module interfaces
- empty implementation stubs

The repository must compile even when physical sensors are disabled through Kconfig.
